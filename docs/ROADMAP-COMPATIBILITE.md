# Feuille de route : compatibilité et découverte automatique

Document de passation. Tout agent (Claude Code, Codex…) qui reprend le travail lit ce fichier d'abord,
met à jour le statut de la tâche qu'il traite **dans le même lot de modifications**, et complète le
journal en bas de page.

Statuts : `À faire` · `En cours` · `Fait` · `Fait (partiel)` · `Bloqué` (raison indiquée).

## Règles à respecter

- **Sécurité matérielle** : un appareil inconnu n'est jamais ouvert ni sondé. Seuls les adaptateurs
  dont le protocole est documenté envoient des commandes, et seulement au modèle ou à la famille
  qu'ils reconnaissent. Toute écriture est relue (ou confirmée par le transport) avant d'être annoncée.
- **Sans matériel sous la main** : un adaptateur écrit d'après une documentation publique est marqué
  « non vérifié sur matériel » dans ses `limitations`, et il démarre en lecture seule quand le
  protocole d'écriture n'est pas certain.
- **Interface en français**, ton et vocabulaire du reste de l'application (voir `README.md`).
- **Tests** : `cd app && npm test` (node --test) et `npm run check` (svelte-check). Chaque tâche
  ajoute ses tests ; la suite doit rester verte.
- **Version et installateur** : après chaque lot, incrémenter la version, ajouter
  `docs/EVOLUTIONS-<version>.md` et la ligne du README, puis lancer
  `powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./Build-Installer.ps1 -Bump -Force`
  (depuis Bash, sortie redirigée vers un fichier). Ne jamais lancer `Build-HubInstaller.ps1`
  directement dans le dépôt, ni `Publish-Update.ps1` sans demande explicite.
- **Licences** : ne pas copier de code GPL (HeadsetControl, OpenRGB, Solaar…). Réimplémenter à
  partir des faits de protocole, et citer la source dans `docs/<FAMILLE>-PROTOCOL.md`.

## Architecture visée

- `app/server/adapters/manifests.mjs` : liste déclarative des adaptateurs (module, export, préfixes
  d'id, logiciels fabricants en conflit, modèles du catalogue avec leurs critères de reconnaissance).
  Le hub, le catalogue, la détection et les verrous fabricant en sont tous déduits.
  **Ajouter un adaptateur = un module dans `adapters/` + une entrée dans `manifests.mjs`.**
- `app/server/hid-channel.mjs` : transport HID commun (ouverture bornée, file série, délai,
  quarantaine après absence de réponse, requête/réponse filtrée). À utiliser pour tout nouvel
  adaptateur HID.
- `app/server/adapter-registry.mjs` : catalogue public et reconnaissance par score
  (`matchHid`) : modèle exact > famille > protocole standard > générique.
